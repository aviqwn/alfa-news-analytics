# Пульс бизнеса

Интерактивный прототип персональной новостной аналитики в интерфейсе Альфа-Бизнеса: событие → контекст компании и роль → факты и позиция банка → условные последствия → уточнение и источники.

**Статус на 26.10.2026: test.** Разборы выполняет собственная логика без LLM. Адаптер OpenRouter / `google/gemma-4-26b-a4b-it:free` подготовлен; проверка 25.10 получила HTTP 429. Успешный live-сценарий не подтверждён, автоматической подмены модели нет. Допустимость выбранного провайдера для сдачи требует подтверждения организаторов.

Этот приватный репозиторий содержит код, синтетический сценарий, разрешённые обезличенные данные кейса и банковские PDF. Отдельный архив не требуется. Для проверки жюри необходимо предоставить доступ аккаунту **alfa-hack-2026**. Секреты и локальные базы не включены. Материалы кейса разрешены для передачи организаторам и приватному GitHub жюри; не делайте репозиторий публичным без отдельного разрешения.

## Запуск после клонирования

Требуется Python **3.12.14**. Основной сервер использует стандартную библиотеку; версии зафиксированы в `.python-version` и `requirements*.txt`. Для запуска в test ключ модели не нужен, `.env` создавать необязательно.

```sh
git clone https://github.com/aviqwn/alfa-news-analytics.git
cd alfa-news-analytics
python3 scripts/run.py
```

Открыть http://127.0.0.1:8000 . Будут использованы включённые профили компаний и банковская аналитика. На localhost вход не требуется. Это демонстрационная авторизация, не банковский SSO.

Полностью синтетический сценарий без данных кейса и ключей:

```sh
python3 scripts/demo.py
```

Запускайте один вариант сервера за раз. Синтетика явно сообщает об отсутствии подтверждённой позиции банка, а не приписывает банку вымышленные утверждения.

## Docker

Полный локальный набор данных монтируется из репозитория:

```sh
docker compose up --build
```

Изолированный синтетический сценарий, без чтения `.env` и вызовов LLM:

```sh
docker compose -f compose.submission.yaml up --build
```

Адрес: http://127.0.0.1:8000 . В разделе «Режим и лимиты» ввести учебный токен приложения `local-demo-only-change-before-sharing`. Это не ключ LLM. Для первой команды требуется Docker Compose с поддержкой `env_file.required`; для офлайн-сценария используйте вторую. Сборка требует загрузки базового образа. **Фактический Docker-запуск на машине подготовки не проверен.** Наличие workflow не означает успешного выполнения CI.

## Сценарий для жюри

1. Выбрать компанию и роль; сравнить персональные ленты.
2. Открыть событие: проверить объяснение значимости для компании.
3. Отделить факт, банковскую цитату и условный вывод; открыть PDF-источник.
4. Задать уточняющий вопрос и проверить сохранение контекста.
5. Добавить новое, явно синтетическое событие и получить новый разбор.
6. Посмотреть трассу, неизвестные сведения, режим работы и ограничения.

Подробности: [сценарий демонстрации](submission/DEMO_SCRIPT.md), [описание проекта](submission/PROJECT_OVERVIEW.md).

## Архитектура и данные

- `backend/`: Python HTTP API, собственный агент, поиск, ранжирование, память, кэш и ограничения обращений к модели.
- `frontend/`: HTML/CSS/JavaScript; оболочка Альфа-Бизнеса, лента, профиль, разбор и вопросы.
- `data/processed/`: три отобранных обезличенных профиля, фрагменты банковской аналитики и происхождение данных. Это не обработка всех компаний набора в интерфейсе.
- `data/raw/companies/`: три исходных CSV; `data/raw/analytics/`: девять банковских PDF.
- `data/synthetic/`: независимые учебные компании и события.
- `docs/АРХИТЕКТУРА.md`: потоки данных, инструменты и меры безопасности.
- `THIRD_PARTY_NOTICES`: компоненты, модели, данные и смоделированные интеграции.

Наблюдаемые признаки отделяются от расчётных и неизвестных. Платежи и общие идентификаторы не считаются доказательством собственности; единицы выручки, размер/валюта долга и другие отсутствующие признаки не выдумываются. Цитаты имеют привязку к документам и страницам. Локальный OCR разрешён организаторами; повторная подготовка OCR использует macOS Vision, а запуск уже подготовленных данных не требует macOS.

## Конфигурация и AI

Шаблон `.env.example` описывает переменные. Основные: `APP_MODE`, `APP_DATA_MODE`, `APP_DB_PATH`, `APP_TOKEN`, `APP_COMPANY_SCOPE`, `APP_ALLOWED_HOSTS`; для модели: `LLM_ENDPOINT`, `LLM_MODEL_ID`, `LLM_API_KEY` и лимиты. Ключ вводится только локально в `.env` или в серверные secrets. Не добавлять его в Git, документ сдачи или клиентский код.

Выбрана Gemma 4 26B A4B, точный настроенный ID `google/gemma-4-26b-a4b-it:free`, endpoint `https://openrouter.ai/api/v1/chat/completions`. Пробный доступ не включает платную замену модели. 20 запросов и 100 000 токенов за 24 часа - локальные инженерные ограничения, не квота провайдера. Неизвестные тарифы и расход не объявляются нулевыми; денежный лимит кейса 500 ₽ учитывается отдельно.

После настройки разрешён один осознанный короткий probe: `python3 scripts/probe_llm.py`. Успех probe ещё не подтверждает качество всей цепочки. До успешного подключения и проверки полного сценария сохранять `APP_MODE=test`.

## Известные ограничения

Живая генерация разрешённой LLM пока не подтверждена: последний запрос получил HTTP 429. Docker-конфигурация подготовлена, фактический контейнерный запуск не проверен. Используются три выбранных профиля; интерфейс не охватывает весь исходный набор компаний. Качество рекомендаций требует экспертной проверки. Доступ к демо предоставляется локальным запуском из этого репозитория.
