# Интерфейс «Пульс бизнеса»

## Направление

Использован `design-taste-frontend`, ветка app screens. Выбран Framed sheet, seed **1767283372**. Перерисовок нет. Сохранены заданные брендовые красный, белый, нейтральные серые и системный шрифт без внешнего CDN. Нейтральная L-образная оболочка держит навигацию и верхнюю строку; основной рабочий экран расположен на белом листе без тени. Знак «А» — текстовая демонстрационная стилизация, не импортированный официальный логотип.

Вопрос экрана: **какое событие заслуживает внимания этой компании и почему?** Главный блок — персональная лента. Собственный элемент продукта — объяснение «Почему это в вашей ленте», связанное с реальными полями API; детальный разбор разделяет факты, позицию банка и интерпретацию. Ни одного декоративного графика или выдуманного KPI.

## Данные и сценарии

- Объекты: компании, роли, события, признаки и происхождение, доказательства, сохранённые разборы, трасса инструментов, оценки.
- Роли: руководитель, финансовый директор, казначей; выбор влияет на запрос ленты и анализа.
- Оболочка главной демонстрирует постоянный вход «Пульс бизнеса» без выдуманных счетов и платежей.
- Персональная лента: поиск, категории из данных, сортировка значимости/даты, импорт нового события и обновление RSS ЦБ.
- Разбор: факт / аналитика банка / интерпретация, действия, ограничения, цитаты, даты, страницы, ссылки, признаки, трасса и проверки.
- Продолжение: уточняющий вопрос и иной разрез с `parent_run_id`; оценка с сохранением в API.
- Компания: происхождение и тип каждого признака, явные неизвестные; исходная выручка не конвертируется в рубли без единиц.
- Режим: конфигурация и блокеры, фактические метрики API; стоимость неизвестна при отсутствии тарифов. Демо не имитирует ответы LLM.
- Защищённый сервер: отдельный токен приложения в sessionStorage; секретный ключ модели остаётся на сервере.
- Данные целиком приходят от API. Нет локальной подмены ответа, случайных процентов, фальшивого банка или придуманных источников.

## Реализация

`frontend/index.html`, `frontend/styles.css`, `frontend/app.js`. Vanilla JS, без npm-сборки и внешних шрифтов. Динамические данные экранированы; ссылки допускают только HTTP(S) и локальные `/sources/`. Семантические формы, видимые состояния фокуса, подписи полей, aria-live, native dialog, reduced motion. На телефоне навигация раскрывается, лента и разбор перестраиваются в одну колонку. Ошибки API видимы, пустая выдача не заменяется шаблонными карточками.

- Браузерный сценарий: 13 проверок пройдены, без JS/console ошибок; 1440/768/390 px, горизонтального переполнения нет.
- `inspect.mjs --app`: 0 FAIL / 0 WARN после исправления мобильного отступа. Просмотрены снимки ленты, разбора и настроек; режимы и предупреждения читаемы.

Изображения не используются: для рабочего интерфейса информационную нагрузку несут события и доказательства. Демонстрационные данные маркируются в источнике/API и отображаются с меткой «Синтетическое событие» / «Синтетические данные». Брендовая оболочка обозначена как прототип, не настоящий банковский кабинет.

## Подключение NIM и независимый учёт

По последующему указанию пользователя добавлено отображение пробного доступа NVIDIA NIM. Режим агента и состояние подключения разделены: `live_verified` означает «Подключение проверено», а `live_ready` без проверки — «Настроено, проверка ожидается». Успешная проверка API не представлена как доказательство работы полной цепочки анализа.

Экран показывает провайдера, точный model ID из health, режим доступа и локальные ограничения пробного режима за скользящие 24 часа (по умолчанию 20 запросов / 100 000 токенов, значения берутся из health). Это инженерные ограничения приложения, не квота NVIDIA. Денежное ограничение кейса 500 ₽ для priced указано отдельно; рублёвая стоимость пробного доступа остаётся неизвестной без подтверждённых тарифов.

Подтверждённые токены берутся из API ledger даже в тестовом режиме агента: отдельная проверка подключения может вызвать модель. Неизвестный расход запросов показан отдельно, не обнуляется. Названия инструментов трассы и проверок переведены на русский, исходные идентификаторы инструментов сохранены для диагностики. Повторная проверка `node --check frontend/app.js` пройдена.

Top three problems (most visible first), each with the screenshot it shows in and the fix:

2. desktop-analysis: интерпретация остаётся длинным абзацем. Следующий шаг — разделить механизмы на короткие доказуемые тезисы после проверки live-модели.
3. mobile-fold: категории требуют горизонтального прокручивания; список намеренно scrollable, но отдельный выбор категории был бы заметнее.

Классификатор исправлен и покрыт регрессионным тестом. Это техническое исправление не заявляется полноценной семантической классификацией.
